  （要往上传才需要权限，那时候再配 SSH。）

 三、装依赖 + 自检
------------------------------------------------------------

  npm install
  npm run check

  只有 jsdom 一个依赖，装得很快。

  预计看到：

      ✓ 全部通过
      ✓ 构建完成
      ★ 全部通过 —— 通过 193 / 失败 0
      ✓ store.js 单测通过：108 条断言

  收藏后端（server/）第一次用要单独装依赖、单独测：

      cd server && npm install && npm test
  → ✓ server 单测通过：35 条断言

  这就是当前的基线。**如果不是全绿，先别改代码**，
  说明环境有问题（多半是 Node 版本太老）。

 五、日常怎么干活
------------------------------------------------------------

  【加一篇新文章】

    # 1. 素材丢进 sources/，纯文本，格式很松：
    #      title: 文章标题
    #      label: Exam Practice Test 1 · Reading Part 4
    #      # 原文     ← 分节标记
    #      （正文，空行分段，空位写成 {16}）
    #      # 选项
    #      A ...
    #
    # 2. 生成骨架
    node tools/new.mjs sources/xxx.txt --slug t5-p2-my-topic

    # 3. 补内容（这一步是真正的工作量）
    #    glossary 词条 / 每句 tr 翻译与 ana 分析 / phrases / 题目解析

    # 4. 自检到 0 错误 —— 它会一条条告诉你还缺什么
    node tools/verify.mjs t5-p2-my-topic

    # 5. 登记进 data/manifest.json 的 books[].articles

    # 6. 全流程
    npm run check

  【改已有的一篇】

    node tools/verify.mjs <slug>
    node build.mjs --only <slug>

  【词库自动长大】200 篇会大量撞词，撞的词不用每篇重写：

    node tools/promote.mjs              # 预览
    node tools/promote.mjs --write      # 真的提到共享词库

  【本地看效果】

    cd dist && python3 -m http.server 8899
    浏览器开 http://localhost:8899/

    ⚠ 首页左上角圆圈点开注册/登录（手机号 + 昵称 + 密码，注册要连后端）。
      本地预览必须起 http 服务，不能双击 html 打开（file:// 存不住登录态）。
      纯看文章不想注册：file:// 打开也行，门禁在存储不可用时放行。

  【后端：收藏 / 注册登录 / 错题落库（server/）】

    cd server && cp .env.example .env && vi .env   # 填 DB_PASS，然后：
    npm install
    npm run migrate              # 建表/加列（幂等；第一次必跑）
    npm run start:env            # 起服务（顺带伺服 dist/，开 http://127.0.0.1:3001）
    npm run selftest             # 真库全链路自检（注册→登录→收藏→错题）

    部署到服务器：
      bash deploy-api.sh --setup <IP>              # 第一次：装 Node、systemd、nginx /api/ 反代
      ssh root@<IP> 'vi /opt/pet-api/.env'         # 填 DB_PASS（不进 git）
      bash deploy-api.sh <IP>                      # 每次发版（会自动跑一遍 migrate）

    没部署也不影响看文章：收藏自动降级成「只存本机 + 联网后补写」，
    注册/登录的弹框会提示「连不上服务器」。

  【改完提交】

    npm run check        # 必须全绿
    git add -A && git commit -m "..." && git push

 七、几个必须知道的坑
------------------------------------------------------------

  【改样式后必须人眼看】
  smoke 测试用的 jsdom 有两条硬限制：没有 matchMedia，
  且 getComputedStyle 完全忽略 @media 规则。
  所以底部抽屉、亮暗配色、触摸设备上的按钮，机器测不到，
  改样式后要在浏览器里过一遍（README 末尾有清单）。

  【别在 :root 之外写颜色】
  颜色一律走语义令牌，暗色只覆写 :root[data-theme="dark"] 里的值。
  直接写 #fff 的地方，暗色主题下就是一块白斑。
  verify 有断言拦这个。

  【分词正则三处必须一致】
  engine/app.js、tools/verify.mjs、tools/new.mjs 里的正则要逐字相同，
  改一处必须同步另外两处，否则词数对不上。

  【切句只是草稿】
  new.mjs 自动切的句子一定会错一些（缩写、引号里的句号）。
  生成后必须人工过一眼 —— 切错了后面全歪。

  【门禁是软门禁】
  密码只在「注册/登录」这一处校验（服务端 scrypt）；进了站之后，
  其余接口还是按手机号认人 —— 纯客户端的那道门，懂技术的人改一下
  localStorage 就绕过了。它现在的目的是让学生注册留号、走一遍流程，不是防人。
  真正的 token 体系要做时另开一轮，别在改别的功能时「顺手」发明半套。

 八、这些文档怎么维护
------------------------------------------------------------

  CLAUDE.md 和 README.md 是活的，改架构、加功能之后顺手更新。
  特别是 README 末尾的「硬规矩」—— 每次踩到新坑就往里加一条，
  那里面每一条都对应一个构建期检查，是这套东西最值钱的部分。

  会话归档（docs/transcripts/）是快照，不是实时的。
  想更新就按 docs/transcripts/README.md 末尾的命令重新导一份，
  但那个文件 9.5MB，在 git 历史里是永久的，别频繁导。
