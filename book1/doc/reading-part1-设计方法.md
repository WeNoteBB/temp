## 一、页面总则（Part 1 专属形态）

Part 1 的页面是**「正文即试卷」**：

| 规则 | 说明 |
|---|---|
| 答题搬进正文 | 文章的 JSON 顶层标 `"inlineQuiz": true` 后，「题目分析」tab 自动隐藏；所有练习在原文里就地作答 |
| 就地判分 | 点选项 → 立即判对错：**答对绿底、答错红底、选中主体色底**；答错自动把「题目解析」写进小黑板 |
| 错题登记 | 答错自动上报错题本（与卡片同一套机制，同题重选不重复登记） |
| 每题必有解析 | 每个答案横排/选项区都带一个「解析」按钮 → 小黑板显示该题完整解析（正确答案/解题思路/答案句拆解/语法/翻译/干扰项） |
| 状态同源 | 正文里的选择和卡片（隐藏的）是**同一份状态**，颜色两边同步；刷新后仍保留 |
| 一行一个解析 | 短文本/选项清单这类碎片内容不逐词查词：**点整行**看这句的讲解 + 页边「析/🔊」 |
| 标题/要求/提示整段处理 | 角色 h/i 的段落（标题、训练①②③④⑤的要求、Remember/Focus 提示、真题抬头）**不给逐句「析」**：整段一个**「译 + 🔊」**，点开只有 **整句翻译 + 解析**（各句 tip 拼接），点句子也是给整段翻译（点单词仍查词）。出题老师的原话：「不需要单独一句句拆出来『析』」 |
| 官方答案 | 所有题目的答案必须先与官方答案页逐题核对，再开始做交互 |

**排版基线（不要动）**：段落角色 `h/i/o/q`、题号徽章 `.pbadge`、选项整行卡（卡片内）、
页边「析/🔊」每句一组。Part 4 的池式页面（`options/optionsAna`）不走这套，保持原样。

## 二、方法代号 A–F（每种题型 → 一种做法）

### 方法 A · 清单匹配型 —— 训练 ①

**教材形态**：上面一张「文本类型」清单（advertisement / label on packet / notice in school /
road sign / sign in park），下面五段编号小文本，让读者把文本与类型配对。

**做成什么样**：

```
A  advertisement   B  label on packet   C  notice in school   D  road sign   E  sign in park
   ↑ 清单行首带字母徽章（一眼看出是选项，不是句子内容）

1  School cafe — opening hours: 10.30–11.00  …        [析] [🔊]
   [A advertisement] [B label on packet] [C notice in school] [D road sign] [E sign in park] [解析]
   ↑ 每段文本下面：答案横排（点一下就是作答）
```

**数据写法**：

```jsonc
// 清单（角色 o 的段落）：行首写 "A "、"B "…，引擎自动把字母拎出来做徽章
{ "s": "A advertisement", "tr": "…", "ana": {…} }

// 五段文本：plain + pick
"blocks": [
  { "r": "o" },                              // 清单（o 自动 plain）
  { "r": "q", "n": "1", "plain": true, "pick": [101] },   // 文本 1 → 题 101
  { "r": "q", "n": "2", "plain": true, "pick": [102] },
  …
]
```

**题号与选项**：`questions[]` 每题一组 `opts`（A–E 与清单同文）、`answer`、`why/clues/others/tip/ana`。

### 方法 B · 成排作答型 —— 训练 ②

**教材形态**：同一批编号文本，问「每段的目的」；选项 a–e 已在原文里列成清单。

**做成什么样**：

```
a  to warn of danger   b  to give information   c  to try to sell something
d  to say what you must not do   e  to say what you must and must not do
   ↑ 小写字母徽章；单击任意一行 → 小黑板解释该选项的意思（行级句子分析）

1  [a to warn of danger] [b to give information] [c …] [d …] [e …] [解析]
2  [a …] [b …] …
   ↑ 清单下面：1、2、3…五排答案区（行号来自题目 tag 尾号）
```

**数据写法**：

```jsonc
// 选项键用小写（与清单行首字母一致）；答案/others 的字母也用小写
"opts": { "a": "to warn of danger", "b": "to give information", … }, "answer": "b"

// 清单之后插一个空块专门放五排答案区：pick 是一个数组 → 渲染成多行（带行号）
{ "r": "q", "pick": [106, 107, 108, 109, 110] },
```

---

### 方法 C · 句内二选一 —— 训练 ③

**教材形态**：句子里给出两个备选词（`mustn't / don't need to`），选正确的那个。

**做成什么样**：

```
1  We [mustn't] / [don't need to] talk when we are doing science exams.
        ↑ 两个备选渲染成虚线框按钮；点一个 → 它变底色，另一个自动取消（单选）
          答对变绿、答错变红；句子其余部分照常可点词查词
```

**数据写法**：

```jsonc
// 句子文本里用 «» 标出两个备选；sent.pickQ 指向题号；字母按出现顺序对应 opts 的键序
{ "s": "1 We «mustn't» / «don't need to» talk when we are doing science exams.",
  "pickQ": 111, "tr": "…", "ana": {…} }
```

**注意**：`«»` 只是渲染标记，不算文字——词数对账、小黑板展示、朗读都会自动剥掉；
verify 会检查「标记数 = 该题选项数、成对闭合」。
③ 的每道题**自动带一个「解析」按钮**（答题解析：正确答案/解题思路/干扰项），
不需要在数据里额外写什么——引擎看到 `pickQ` 就会补上。

---

### 方法 D · 单词选项型 —— 训练 ④

**教材形态**：一组填空题，选项是固定单词表（must / have to / mustn't / don't have to）。

**做成什么样**：

```
1  Do you …………… get up early every morning?
   [A must] [B have to] [C mustn't] [D don't have to] [解析]
   ↑ 每道题下面都有全表选项（用户明确要求：must / have to / … 每题下面都有）
```

**数据写法**：

```jsonc
【{ "r": "q", "pick": [115] }  // 每题一块，pick 只放自己那题
"opts": { "A": "must", "B": "have to", "C": "mustn't", "D": "don't have to" }
```

---

### 方法 E · 短文本 + 横排 —— 训练 ⑤（message / email 类）

**教材形态**：几段较长的编号文本（短信、贺卡、邮件、通知），问「写作目的」等问题。

**做成什么样**：文本**保持承诺的逐词精读**（每个词可点、词组标黄、每句「析/🔊」），
只在每段文本下面加一排答案横排 + 「解析」。用户对 ⑤ 的定调：「只需要解析和喇叭就可，保持现状」。

**数据写法**：

```jsonc
{ "r": "q", "n": "1", "pick": [121] }   // 不加 plain：文本照旧可逐词查
```

---

### 方法 F · 整行选项型 —— 真题（A/B/C 长选项）

**教材形态**：五段编号文本，每题三个长句选项 A/B/C。

**做成什么样**：

```
1  Anton, when you see your sister at the basketball match later, …
   ┌────────────────────────────────────────────────────────────┐
   │ (A) Anton has to check his sister knows about the …   析 🔊 │  ← 点整行 = 选它
   ├────────────────────────────────────────────────────────────┤
   │ (B) Anton should remind his sister to switch her …    析 🔊 │
   ├────────────────────────────────────────────────────────────┤
   │ (C) Anton needs to ask his sister if she's taking …   析 🔊 │
   └────────────────────────────────────────────────────────────┘
   [看本题解析]
   ↑ 单选变底色（对绿错红）；行内「析」= 这个选项的句子分析（做法同 Part 4 选项池）
```

**数据写法**：

```jsonc
"blocks": [ { "r": "q", "n": "1", "optsInline": true }, … ]   // 题号取 n（1–5）

"questions": [{
  "n": 1, "answer": "A",
  "opts": { "A": "…", "B": "…", "C": "…" },
  "optsAna": {                       // 每个选项的句子分析（parts/gram/tr 必填）
    "A": { "parts": [["主语","Anton"], …], "gram": ["have to 表客观必须", …], "tr": "…" },
    "B": { … }, "C": { … }
  },
  "why": "…", "clues": […], "others": [["B","…"],["C","…"]], "tip": "…", "ana": {…}
}]
```

**约定**：点选项里的**单词**=查词（不触发作答）；点行内其它区域=作答；
「看本题解析」= 完整题目解析。这条与卡片里的选项整行行为完全一致。

## 三、数据字段速查（只列「设计方法」相关）

| 位置 | 字段 | 作用 |
|---|---|---|
| 顶层 | `inlineQuiz: true` | 该文章答题全在正文页；隐藏「题目分析」tab |
| `passage.blocks[i]` | `r: "h"/"i"/"o"/"q"` | 段落角色：h 标题加粗 / i 提示斜体浅灰 / o 选项清单强调色 / q 题目文本块（左侧标线） |
| 同上 | `n: "1"…` | 文本块的题号徽章；`optsInline` 用它找题目 |
| 同上 | `plain: true` | 这块不逐词查词（角色 o 自动 plain）；样式不变，点整行仍是讲解 |
| 同上 | `pick: [题号…]` | 在这块下面渲染「我的答案」横排；数组长度 >1 时自动带行号（取 tag 尾号） |
| 同上 | `optsInline: true` | 把该题（n）的 opts 整行列进正文（方法 F） |
| `sentence` | `pickQ: 题号` | 句内 `«…»` 备选词按钮挂在哪个题上（方法 C） |
| `sentence` | 文本里的 `«»` | 句内二选一的渲染标记（不算文字） |
| `question` | `tag: "①-1"` | 徽章/标题用（训练题），横排行号取短横线后的部分 |
| `question` | `opts: {…}` | 每题自带选项（Part 1 式）；键可大写（A–E）也可小写（a–e，与原文清单一致） |
| `question` | `optsAna: { 字母: {parts, gram, tr} }` | 选项的句子分析（方法 F 必填；verify 强制） |
| `question` | `answer/why/clues/others/tip/ana` | 判分与「解析」按钮的数据源 |

## 四、引擎行为速查（做新文章不需要动引擎，但改引擎时要护住）

| 标记 | 行为 |
|---|---|
| `data-ansb="题号:字母"` | 点它 = 作答（单选，全页同题号一起变色：`.on` 选中 / `.right` 答对 / `.wrongpick` 答错） |
| `data-qexp2="题号"` | 「解析」按钮：小黑板显示该题完整解析并自动展开 |
| `data-ana="qo:题号:字母"` | 选项行内的「析」：该选项的句子分析（数据取 `q.optsAna`）；点它不会作答 |
| `data-sayraw="句子"` | 选项行内的「🔊」：朗读该选项；点它不会作答 |
| `data-ana="段-句"` / `data-say="段-句"` | 页边「析 / 🔊」（每句）；句子在黑板的句型 chip 可标红对应成分 |
| `data-ana="blk:段号"` / `data-say="blk:段号"` | 页边「译 / 🔊」（h/i 整段）：小黑板只出**整段翻译 + 解析**（各句 tip），没有句型/成分拆解；点这类段落里的句子走的也是它 |
| `.para.plain` | 里面的 `.w` / `.ph` 不响应点击（仍保留黄色词组标） |
| `.pickrow` / `.pickchip` | 答案横排 / 横排里的选项胶囊 |
| `.pickword` | 句内备选词按钮（虚线框） |
| `.optline` | 正文里的整行选项（点行作答） |
| `.opletter` | 选项清单行首的字母徽章 |

**颜色规则（全站一致）**：未作答=面板底；`.on`=主题蓝底白字；`.right`=绿（答对）；
`.wrongpick`=红（答错）。窗口窄时横排自动折行，选项行文字列自动占满。

## 五、内容约定（每次做 Part 1 都必须遵守）

1. **答案先官方核对**：拿到官方答案页（Teacher's Notes & Keys）逐题核对后才写入数据；
   推断出来的答案必须在 `note` 里标注「待核对」。
2. **一行一个解析**：短文本、选项清单不逐词做词条解释；点整行看讲解。
3. **词表覆盖率 100%**：原文 + 选项的每一个词形都要有词条（verify 强制）。
4. **每段碎片文本都有自己的句子分析**（`tr` + `ana` 完整七字段），页边按钮一一对应。
5. **训练题编号从 101 起**（tag 如 ①-1、⑤-4），真题保持 1–5；
   每篇文章的题号在错题本里靠 `slug + n` 唯一。
6. **选项文本照抄试卷**（含标点风格）；`others` 要覆盖每一个错选项。

## 六、制作流程与验收（新文章的固定流水线）

1. 内容入数据：`pet-reading/articles/<slug>.json`（按第三节字段写）
2. `node tools/verify.mjs` —— 数据契约全绿（含本设计的扩展检查：
   `pick` 题号存在、`optsInline` 每题都有 `optsAna`、`pickQ` 的 `«»` 成对且数量=选项数）
3. `node build.mjs` → `dist/`；`node tools/smoke.mjs` —— 端到端断言全绿
   （本设计新增断言：隐藏 tab、清单徽章、横排单选/变底色/卡片同步、句内二选一、
   整行选项作答、行内「析」出句子分析、点词不作答、plain 不查词、解析按钮出完整解析）
4. `bash deploy.sh <服务器>` 部署
5. **真浏览器截图逐屏自检**（手机 420px + 桌面 1280px + 暗色三档），
   重点看：横排折行、选项行颜色、黑色板解析内容、悬浮态
6. 全量测试收尾：verify / smoke / test-store / server 四个套件全绿
