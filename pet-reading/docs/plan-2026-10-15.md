# PET 精读：三端适配 + 黑暗模式 + 登录门禁 + 收藏接口

## Context

`pet-reading/` 目前是「引擎 / 内容分离」的纯静态站：引擎（`engine/app.js` + `style.css` + `template.html`）全站共用，每篇文章一个 JSON，`node build.mjs` 产出 `dist/`，部署在 2核2G 的 nginx 上。当前管线全绿（verify ✓ / build ✓ / smoke 110 断言 ✓）。

本次要加四件事：

1. **手机 / iPad / 电脑三端适配** —— 当前只有 1180px 一个断点，手机上页边按钮被整个隐藏，讲解面板堆在正文下方（点了当下看不到，要往下滚）。
2. **黑暗模式** —— 目前零主题痕迹。
3. **web 登录页 + 强制门禁** —— 未登录看不了任何正文。
4. **收藏按钮** —— 历史列表每行右侧一个 ☆，点击写入收藏；真实存储（数据库表）留接口，之后再做。

## 已确认的四条口径

| # | 决策 | 含义 |
|---|---|---|
| 1 | **纯前端，但预留后端** | 登录态与收藏先存 localStorage，但所有读写走一层薄适配器 `engine/store.js`，接口从第一天起就是 `async`。将来接后端只改这一个文件，页面代码一行不动。 |
| 2 | **手机端讲解面板 = 底部抽屉** | 抽屉顶部自带 🔊，所以页边那排「析/🔊」按钮在手机上不需要恢复。 |
| 3 | **强制登录** | 未登录访问任何文章页 → 跳登录页，登完回原页。 |
| 4 | **收藏只在历史列表里** | 不做收藏列表面板。历史浮层每行的词右侧加一个 ☆（与现有 ✕ 并排）。点击写一条收藏，接口留好、真实存储后补。 |

## 必须让用户知道的三个后果

强制登录（决策 3）会连带产生三个影响，**实施前要在 README 里写明**：

1. **搜索引擎收录不到**。200 篇内容不再公开可索引。
2. **微信/QQ 里转发链接，对方打不开正文**（会落到登录页）。如果以后要做传播，得改成「试读 N 篇」。
3. **`file://` 双击打开彻底失效**。原本 `dist/` 里的 HTML 双击就能跑（引擎全是相对路径、普通 `<script>`）；加了门禁后本地打开会跳登录页，而 `file://` 下 localStorage 不可靠 → 登录永远存不住。**因此门禁必须「存储不可用时放行」，否则本地打开会变成无限跳转**（见第 4 步的安全设计）。

另外要说清：**客户端门禁只是软门禁**，懂技术的人改一下 localStorage 就绕过了。真正的门禁要等后端。在没有后端之前，它的作用是「让学生走一遍登录流程、把手机号留下来」，不是防住谁。

## 前置事实（探查结论，实施时直接采信）

- **`build.mjs:114-121` 的孤儿清理是新增页面的硬墙**：它扫 `dist/` 顶层所有 `.html`，文件名不在 manifest slug 集合里就删（连 `.gz` 一起），唯一豁免是 `index.html`。`dist/login.html` 会被下次构建删掉。
- **`build.mjs:72` 的引擎文件同步是写死的两个文件名**；`renderIndex`（`:185`）也只引用 `style.css?v=${V_CSS}`。新共享资源不会被复制进 `dist/engine`，引用必 404；新资源也没有 `?v=` 缓存失效。
- **`app.js:4` 无条件读 `window.PET_CONTENT`** —— 登录页若加载 app.js 但页面没有 PET_CONTENT，初始化即崩。
- **`--zoom` 有 50 处 `calc(Npx * var(--zoom))`，分布 42 行**，列内元素全部显式乘，不依赖 em 继承。
- **`style.css` 有 67 行硬编码颜色**（`--*` 之外直接写色值）。这才是黑暗模式的真正工作量，不是加个 `[data-theme=dark]` 就完事。
- **两个已有的移动端 bug**：`.hdel{opacity:0}`(`style.css:273`) 靠 `:hover` 显形 → **触摸设备永远点不到历史条目的删除按钮**；`.hist-float`(`:94`) 固定 `width:330px`，375px 屏幕上溢出，且顶栏 `flex-wrap:wrap` 折行后实际高度远超 `top:64px`，浮层会盖住顶栏。
- **历史三件套是收藏按钮的现成挂点**：`histKey(it)`(`app.js:456`) / `pushHistory`(`:458`) / `renderHistory`(`:477-511`)，每行 `div.hitem` 内已并排两个 button（`.hopen` 与 `.hdel`，`:493` 与 `:507`）。**`bindHistory`(`:1138-1158`) 已经在委托 `[data-histdel]` / `[data-hist]`，☆ 加进来是同一个模式的第三个分支**，不需要碰 `bindPassage`。
- **`lookup()`(`app.js:182-209`) 会做屈折回退**，返回 `{key, entry, matched}`，`key` 是**词典原形**。点 `centuries` 拿到 `century` —— 收藏必须存这个原形，否则同一词的不同形式会各收藏一条。
- **历史里的词组也记成 `t:"w"`**(`:1101`)，所以历史表分不出词和词组；收藏若要区分，得靠 `C.phrases` 数组判定。

## 实施步骤

### 第 0 步：泛化 build.mjs（一切新页面的前提）

**改 `build.mjs`**，四件事：

1. **页面注册表**。把 `index.html` 从特例提升为注册表的一员：

   ```js
   const PAGES = [
     // 注意 renderIndex 现有签名是 (man, slugs)，参数顺序别写反
     { out: "index.html", render: () => renderIndex(manifest, flat.map(x => x.slug)) },
     { out: "login.html", render: () => renderLogin(manifest) },
   ];
   ```

   孤儿清理的豁免名单改为 `new Set(PAGES.map(p => p.out))`，别再往第 115 行堆特例。

2. **引擎资源改为扫描目录**。删掉写死的两文件数组，改成扫 `engine/` 下的 `*.js` / `*.css`：

   ```js
   const assets = fs.readdirSync(P("engine"))
     .filter(f => /\.(js|css)$/.test(f))
     .map(f => ({ name: f, body: read(P("engine", f)), hash: hash(read(P("engine", f))) }));
   const V = Object.fromEntries(assets.map(a => [a.name, a.hash]));
   ```

   同步时遍历 `assets`。模板里新增**通用占位符 `<!--V:文件名-->`**，`render()` 用一条循环替换掉所有 `<!--V:xxx-->`；现有的 `<!--V_CSS-->`/`<!--V_JS-->` 一并迁到新语法，别混着留两套。

3. **修 `--only` 截断目录页**：`renderIndex` 现在拿的是本轮 `builtSlugs`，改成全量 slug（上面 `render` 里已经这么写了）。

4. **修静默失踪**：manifest 指向的文章文件不存在时（`:86` 的 `continue`）现在是静默跳过，改成收集起来，构建末尾报错并非零退出。

**验证**：`node build.mjs` 后 `dist/` 与现在一致（回归）；`node build.mjs --only <slug>` 后 `dist/index.html` 仍列全部文章。

### 第 1 步：`engine/store.js` —— 预留后端的那个缝

新建 `engine/store.js`，普通 `<script>` 注入全局 `window.PETStore`（app.js 是 IIFE 无模块，只能走全局）。**不依赖 `PET_CONTENT`**，所以登录页也用它。

```js
window.PETStore = (function () {
  // 全部 async —— 今天包的是 localStorage，将来换成 fetch 时调用方一行不改。
  // 这是「预留后端」的全部秘密：把异步性前置，而不是等到接后端时再回来改所有调用点。
  return {
    // 可用性：隐私模式 / file:// 下 localStorage 会抛，调用方据此决定是否放行
    available,          // () → boolean

    // 登录态（跨篇共享，键不带 slug，遵守 app.js:10-13 的命名约定）
    getUser,            // async () → { phone, ts } | null
    login,              // async (phone) → { ok:true, phone } | { ok:false, err }
    logout,             // async ()

    // 收藏 —— 先把界面和接口做出来，真实存储（数据库表）之后接
    addFav,             // async (item) → { ok, added }
    isFav,              // async (id) → boolean
    listFav,            // async () → [item]   （界面暂不用，留给以后）

    // 主题
    getTheme,           // async () → "auto"|"light"|"dark"
    setTheme            // async (t)
  };
})();
```

存储键（跨篇的都不带 slug）：`pet:user:v1`、`pet:fav:v1`、`pet:theme:v1`。所有访问照 `app.js` 的风格包 try/catch。

**收藏条目的形状与唯一 id**：

```js
{ type:"w"|"ph"|"s", key, ref, slug, cn, ts }   // 单词/词组存 key，句子存 ref
id = type === "s" ? "s:" + slug + "@" + ref : type + ":" + key
```

单词/词组的收藏是**全局按词**的（同一个词在任何文章里都是同一条）；句子按篇（`ref` 只在它自己那篇里有意义）。

> **这里就是「留给数据库的接口」。** 现在 `addFav` 往 `pet:fav:v1` 里追加（同时天然成为将来补写数据库的 outbox）；`isFav` 从它读。以后接后端，只把这两个函数体换成 `fetch`，`bindHistory` 里那一行调用不动。

**验证**：新建 `tools/test-store.mjs`，在 Node 里塞一个假 `localStorage` 直接跑 `store.js`，断言手机号校验、收藏去重、`isFav` 一致性、主题读写、以及**假一个会抛异常的 localStorage，断言 `available` 返回 false 而不是抛出去**。这个测试很便宜且价值高，因为 store 是将来唯一要动的文件。

### 第 2 步：黑暗模式

**策略：先把 67 行硬编码色提升为语义令牌，再定义暗色值一次。** 不要写 67 条暗色覆盖规则 —— 那样以后每加一个组件都要记得配两遍。

**新增语义令牌**（按那 67 行的实际重复度归并）：

| 新令牌 | 收拢的现有硬编码 |
|---|---|
| `--ok` / `--ok-bg` / `--ok-line` | `#1d7a45` / `#c9ecd5` / `#eefaf1`（绿色家族，散落约 8 处） |
| `--danger` / `--danger-bg` | `#d64545` / `#fdeaea`（删除、朗读中，约 6 处） |
| `--warn` / `--warn-bg` / `--warn-line` | `#a8641a` / `#fdf3e3` / `#f2ddb8` |
| `--hl` / `--hl-2` / `--hl-peek` | 句子高亮三态 `#c9ddff` / `#dceaff` / `#ffd6e8`（`:167/169/170`） |
| `--chip-*` ×4 | `.chip.cl` / `.chip.ph2` / `.chip.gr` / `.chip.pat`（`:352-366`） |
| `--code-bg` / `--code-ink` | `#eef1f6` / `#b3402f`（`:344-345`、`:470`，重复两次） |
| `--scroll` | 滚动条 `#d6dce8` / `#c2cbdb` |
| `--on-accent` | 那 14 处 `color:#fff`（彩色底上的白字） |

- **`--shadow`** 值里含颜色，两个主题各覆写一次（暗色更黑、alpha 更高）。
- **`--hard` / `--hard-bg` 是死令牌**（定义但 0 处使用），顺手删掉。
- **4 处 `!important`（`:167/169/170`）不用动** —— 颜色走令牌后，暗色值通过令牌换，不需要跟 `!important` 抢优先级。
- **`.part code` 的 `rgba(128,128,128,.2)`(`:381`) 是全文件唯一天然暗色友好的写法**，改造照这个范式（半透明中性色）走，能少一半令牌。

**切换机制**：
- `:root[data-theme="dark"]{ …令牌覆写… }` 一个块，CSS 只认显式属性。
- **防闪烁（FOUC）**：主题属性只能由 JS 写，而 CSS 是外链、会阻塞渲染 —— JS 跑完前会闪一帧亮色。在 `<head>` 里、**样式表之前**放一段**内联** `<script>`，同步读 `pet:theme:v1` 并写 `data-theme`。这是唯一的正解（这段脚本要极小，且本身不能依赖 store.js）。
- `auto` 由内联脚本启动时解析成具体值写死，避免 CSS 里再维护一套 `@media (prefers-color-scheme)`；JS 另挂 `matchMedia('(prefers-color-scheme: dark)')` 的 change 监听，在 `auto` 模式下跟随系统。
- **切换按钮**：`.tools` 里加三态循环按钮 `#tglTheme`（跟随系统 → 亮 → 暗）。
- `<head>` 补 `<meta name="color-scheme" content="light dark">` 与 `<meta name="theme-color">`。

**验证**：机器只能测「点按钮后 `data-theme` 与 localStorage 变了」（加进 smoke）；**颜色本身必须人工在浏览器里看**（jsdom 不算样式）。覆盖：正文、词组黄底、句子交替底色、三态高亮、题目区、选项对错、小黑板全部区块、历史浮层、登录页。

### 第 3 步：三端适配

**断点重新划分**（现有唯一断点 1180px 正好卡在 iPad Air 横屏上，iPad Pro 11" 横屏 1194px 反而不命中 —— 这个值要废掉）：

| 区间 | 布局 | 页边按钮 |
|---|---|---|
| `≥1100px` | 两列（现状） | 保留 |
| `<1100px` | 单列正文 + 小黑板变**底部抽屉** | 隐藏（抽屉顶部自带 🔊） |

**底部抽屉**——关键设计：**复用同一份 `#colAna` DOM，只用 CSS 换表现**，不新增面板。现有 `.hide-ana` 的显隐逻辑（`applyCols()` 切 class）完全不动：

```css
@media(max-width:1099px){
  #colAna{
    position:fixed;left:0;right:0;bottom:0;z-index:60;
    height:62vh;border-radius:16px 16px 0 0;
    transform:translateY(100%);transition:transform .22s ease;
    padding-bottom:env(safe-area-inset-bottom);
  }
  .cols:not(.hide-ana) #colAna{transform:translateY(0)}
}
```

配一个拖拽把手（`.col-head` 加 `::before` 横条）与遮罩层；viewport 补 `viewport-fit=cover`，加 `-webkit-text-size-adjust:100%`。

**顺带修掉已存在的移动端问题**：
- `.hdel` 触摸不可点 → `@media(hover:none){ .hdel{opacity:1} }`（一行）。☆ 按钮加进来时**必须一并纳入这条规则**，别重蹈覆辙。
- `.hist-float` 手机上溢出且盖住顶栏 → 窄屏改为 `left:14px;right:14px;width:auto`，`top` 不再写死 64px。
- `body{height:100vh}` → 补 `height:100dvh`（iOS Safari 会把它算进地址栏，抽屉会被顶掉一截）。

**验证**：jsdom 不做排版，这一整步**只能人工在浏览器里量**。用 Playwright 在 375 / 768 / 1024 / 1180 / 1440 五个宽度逐档截图 + 实测（抽屉能否拉起、正文有无横向溢出、页边按钮在 ≥1100 时是否仍精确对齐、历史浮层不盖顶栏）。

### 第 4 步：登录页 + 强制门禁

**登录页**：
- 新建 `engine/login.template.html`，由第 0 步的注册表渲染成 `dist/login.html`。
- **不加载 `app.js`**（`app.js:4` 会因缺 `PET_CONTENT` 崩，且登录页不需要引擎）。只加载 `engine/style.css`（拿令牌与暗色）+ `engine/store.js` + 页内一段自己的 `<script>`。
- 手机号校验 `/^1[3-9]\d{9}$/`；成功后 `store.login(phone)` 再跳 `next` 参数指定的页面（默认 `index.html`）。
- 顶部显示**脱敏**号码：`138****8000`。

**门禁**（这是本次最容易写出事故的一处，五条都要做到）：

1. **门禁逻辑写进 `store.js` 旁边的一个共享片段**，文章页与目录页共用，别在两处各写一遍。
2. **`app.js` 的 `init()` 开头检查**；未登录 → `location.replace("login.html?next=" + encodeURIComponent(当前路径))`。用 `replace` 不用 `href`，免得用户按返回键在登录页和文章页之间来回弹。
3. **`index.html` 也要门禁** —— 它是 `build.mjs:renderIndex()` 生成的独立页面，目前不加载 app.js。给它加 `store.js` + 一小段内联门禁脚本。
4. **失败必须放行，不能无限跳转**：`store.available === false`（隐私模式 / `file://` / 存储被禁）时**直接放行**，只提示「当前浏览器无法保存登录状态」。否则登录页存不住 → 跳回来 → 又跳过去，成了死循环。这是本步最关键的防御。
5. **登录页自身不再门禁**，且 `next` 参数要做同源校验（只接受站内相对路径），防止被当成开放重定向跳去外部站点。

**手机号「带到每个页面」的注入点**：`template.html:13` 的 `.brand` 右侧加 `<span class="who" id="who"></span>`，由 `app.js` 的 `init()` 里 `await store.getUser()` 填成脱敏号码 + 一个「退出」入口。

**验证**：smoke 加 `testLoginPage()`（驱动表单、断言跳转与 store 状态）+ 文章页未登录时跳转、已登录时正常渲染两条断言。

### 第 5 步：收藏按钮（缩小后的一步）

**UI**：`renderHistory()`(`app.js:477-511`) 里每行的 `.hopen` 与 `.hdel` 之间插一个 ☆：

```js
h += '<button class="hfav" data-fav="' + esc(id) + '" title="收藏">☆</button>';
```

**绑定**：`bindHistory`(`app.js:1138-1158`) 里加第三个分支，照现有 `[data-histdel]` 分支的形状写：

```js
var fv = ev.target.closest("[data-fav]");
if (fv) {
  ev.stopPropagation();               // 别让它冒泡到同一行外面的 .hopen
  store.addFav(itemOf(fv.dataset.fav)).then(function (r) {
    fv.classList.toggle("on", r.added);  // 点亮
  });
  return;
}
```

`itemOf(id)` 从 `state.hist` 里按 id 找回那条记录，再补上 `slug` / 展示文本 —— **注意用 `lookup()` 解析后的词典原形当 `key`**，不是用户点击到的屈折形式。

**样式**：`.hfav` 与 `.hdel` 同款，但**必须进 `@media(hover:none)` 的常显名单**（见第 3 步），否则在手机上又是看不见点不到。

**验证**：smoke 加断言 —— 点词进历史 → 行内有 ☆ → 点 ☆ → `pet:fav:v1` 多一条且 ☆ 点亮 → 再点一次取消 → **换一篇点同一个词，`isFav` 仍为真**（跨篇一致性）。

### 第 6 步：测试与文档

- **`tools/verify.mjs`**：内容是数据校验，登录页/收藏不归它管；只加一条「`engine/store.js` 存在且不含 `PET_CONTENT` 依赖」，防止以后有人把引擎依赖混进 store。
- **`tools/smoke.mjs`**：
