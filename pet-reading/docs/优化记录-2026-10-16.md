# 优化记录 · 2026-10-16 · 收藏落库全链路

> 一句话：**单词/句子收藏从「只存浏览器本地」升级为「落进 MySQL + 离线兜底 + 跨设备恢复」，并部署上线。**

---

## 一、优化概述

- **背景**：收藏此前只写 localStorage，换设备/清缓存就丢；数据库表
  （`pet_word` / `pet_sentence` / `user_word` / `user_sentence`）虽已建好，但没接上。
- **目标**：收藏落进 `bud` 库；单词表字段带全；断网也能收藏；上线可验收。
- **结果**：全链路完成并部署到 `8.138.161.122`，公网端到端、真库自检、
  本地全部测试均通过；旧数据用补全工具刷过一遍。

## 二、具体优化的内容

1. **新增收藏后端** `server/`（Express + mysql2，5 个接口）：
   - 登录按手机号自动建号（level 默认 A1）；收藏时 `pet_word` / `pet_sentence`
     没有就插（句子按 `sha256(trim(句子))` 去重），再写 `user_word` / `user_sentence`
     关联行；取消收藏只删关联，公共词句库不动。
   - `level` 写 `PET`、`source_type=2`（文章）。
2. **单词字段带全（bug 修复）**：收藏单词时带上
   音标、词性、**点它时所在的原句**（连同翻译/分析）、含它的搭配；
   例句同时写进 `pet_sentence` 并补 `sentence_hash`（去重/关联成立）。
   `mnemonic` 内容里没有 → 留空等补全流程；`status/source/retry_count/时间` 走库默认。
3. **前端改造** `engine/store.js` + `app.js`：
   - 本地即时（星星不等网络）+ **补写队列**（断网攒着、联网自动推）；
   - **拉取合并**：换设备登录后从服务器恢复星标；
   - 句子收藏身份 = 句子文本；点词时记下所在句子的 ref。
4. **旧数据补全** `server/backfill.mjs`：拿文章内容库把 `pet_word` 里缺的字段补齐
   （15 个词全部补上音标/词性/例句/搭配），只填空字段、幂等、可反复跑。
5. **部署上线**：Ubuntu 22.04 + nginx，Node 22 旁装 `/opt/node-v22`（不动系统 node），
   systemd 服务 `pet-api`，nginx `/api/` 反代。
6. **测试与文档**：store 单测 114 条、后端单测 42 条、smoke 193 条全绿；
   README / CLAUDE / START-HERE / server 文档同步更新。

## 三、技术方案

| 层 | 方案 |
|---|---|
| 静态站 | 仍是纯静态（nginx），引擎与内容分离，构建产物 `dist/` |
| 接口 | 同源 `/api` 由 nginx 反代到 `127.0.0.1:3001` 的 Node 服务，无跨域问题 |
| 数据 | Express + mysql2，SQL 集中在 `server/db.mjs`；`INSERT ... ON DUPLICATE KEY UPDATE id=LAST_INSERT_ID(id)` 拿既有 id，重复收藏不覆盖（先到先得） |
| 离线 | store.js「本地即时 + outbox 补写队列」：增删按序入队，联网自动推送；400 永久失败的条目丢弃（防堵队），网络失败留在队列下次再推 |
| 句子身份 | `favId = s:<句子文本>`；hash 只在**服务端**算 —— 页面在 http:// 下没有 `crypto.subtle`，客户端算不了也不该算 |
| 例句关联 | 收藏单词时例句镜像进 `pet_sentence`（同一套 hash 去重），`pet_word.sentence_hash` 从第一天可关联 |
| 补全工具 | `backfill.mjs` 从 `articles/*.json` 反查词条/例句/搭配；词形回退规则照抄 `app.js` 的 `lookup()`，两端不漂移 |
| 部署 | `deploy-api.sh [--setup] <IP>`：旁装 Node 22 → systemd → nginx 反代 → 上传重启 → 健康检查；密钥/口令不进 git |
