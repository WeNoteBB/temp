# PET 词组库 · 产品与架构设计

> 一句话：把 254 组固定搭配（原稿）升级成一座**词组库** —— 内容自带「题目 + 选项 + 解析」，
> 学习走**精读模式**（原题 · 小黑板 · 历史），复习走**小霸王学习模式**（自动播放 → 连线 → 选择题 → 自动批改）；
> 收藏进「我的词书」，错题进「词组错题本」。

## ✅ 决策已定（2026-10-18 晚，老师拍板）

| # | 问题 | 定了 |
|---|---|---|
| 1 | 选择题怎么出 | **本组 10 个词组当选项**：题干 = 原句挖空（中文 + 用法两条线索），点一个**立刻判分并自动进下一题**（你原话的「10 选 1」） |
| 2 | 点单词看什么 | **词组可点 + 单词给读音/释义/相关词组**；词典分批补（落点是 `data/phrases.dict.json`，每批上线时把这批例句里的生词补齐） |
| 3 | 表怎么建 | **新开三张**：`pet_phrase`（内容镜像）/ `user_phrase`（用户词组，带 5 个字段的快照）/ `pet_phrase_mistake`（词组错题）；阅读的老表和接口一个字节不动 |
| 4 | 内容真源 | **`data/phrases.json` 真源 + DB 镜像**（构建期内联进页面，页面不依赖接口） |
| 5 | 跟读 mp3 | **先只用 TTS**（英音 0.75 倍速，自动播放默认静音、可跳过；音频等页面稳了再说） |

两个模式的名字：**精读模式**（手动，一次一张卡）＋ **小霸王模式**（自动/闯关）。

## 2. 产品设计

### 2.1 一条词组 = 一个内容单位

| 字段 | 例子 | 从哪来 |
|---|---|---|
| `n` / `grp` | 1 / 1（第 1 组） | 原稿序号（10 个一组） |
| `ph` 词组 | a couple of | 原稿「短语」列 |
| `alt` 等价说法 | = groups of | 原稿里 `A = B` 的写法 |
| `cn` 中文意思 | 几个；一对；一双 | 原稿 |
| `use` 用法 | 后接可数名词复数 | 原稿「短语用法」 |
| `ex` / `exCn` 例句 / 翻译 | Anyway, a couple of months ago… / 不管怎样… | 原稿 |
| `blank` 挖空块 | a couple of | 生成（短语在句中的实际形态，必须是 `ex` 的子串） |
| `why` **答案分析** | 空后是 months（可数名词复数）…… | 新增（我起草 + 老师审） |
| `trap` 易错点 | a number of 也能接复数名词…… | 新增（最容易被选走的那个为什么不成立） |

题目形态（已定）：**题干 = 原句挖空，选项 = 本组另外 9 条 + 正确答案本身（共 10 个）**，
中文 + 用法作线索（和书上练习题一样），点一个立刻判分、自动进下一题。
所以「选项」不用另写 —— 它就是这一组的 10 个词组；要写的只有 `why` / `trap` 两句解析。
`data/phrases.dict.json` 是随页小词典（例句里出现的词，分批补）。

### 2.2 精读模式（原题 · 小黑板 · 历史 —— 和 Reading Part 一模一样的三件套）

```
┌ 顶栏：← 首页 · PET 词组库 · 第 1 组 · [经典模式|小霸王模式] · ◐主题 ─┐
│ ┌── 左列：一次一张卡 ─────────────┐ ┌── 右列：小黑板 ────────────┐ │
│ │ ‹ 3/10 ›   ☆   🔊             │ │ （点词组）a couple of      │ │
│ │ a couple of  几个；一对；一双  │ │   几个；一对；一双          │ │
│ │ 用法：后接可数名词复数          │ │   用法：后接可数名词复数     │ │
│ │ Anyway, a couple of months ago │ │   例句 + 翻译 + 🔊          │ │
│ │ I saw someone playing the     │ │   ☆ 收藏 · 历史记录        │ │
│ │ piano on TV – he was brilliant│ │                            │ │
│ │ 不管怎样，几个月前…            │ │ （点单词）piano 🔊 + 同族词组│ │
│ └───────────────────────────────┘ └────────────────────────────┘ │
│  历史浮层（右侧滑出）：点过的词组 / 单词，点一条回到小黑板           │
└──────────────────────────────────────────────────────────────────┘
```

交互清单：

| 动作 | 结果 |
|---|---|
| 点**词组**（卡片里的、例句里的其他词组） | 小黑板出词组条（中文 / 用法 / 例句 + 翻译 / 解析 / 🔊 / ☆ 收藏） |
| 点**单词** | 小黑板出单词条：读音 + 释义（随身小词典）+ **相关词组**（含这个词的词组、例句里出现这个词的词组）+ ☆ |
| ☆ 收藏 | 本地立即点亮 → 队列推后端；「我的词书」里词组独立成段 |
| 🔊 | 英音 0.75 倍速（与文章页同一口径）：卡片上短语、例句各一个 |
| ← / → 或点两侧箭头 | 上一张 / 下一张；顶部 `3/10` 进度 + 一条细进度条 |
| 点历史行 | 小黑板重现那条 + 高亮 |
| 一组看完 | 卡片底部「进小霸王模式 →」 |

### 2.3 小霸王学习模式（三关 + 自动批改）

| 关 | 玩法 | 数据 |
|---|---|---|
| ① 自动播放 | 10 张卡自动翻页，每张自动读「词组 → 例句」；可 ⏸ 暂停 / ‹ 上一张 / 下一张 › / 调速（3–8 秒/张）/ 静音。进度 1→10 | 本地，不落库 |
| ② 连线 | 左 10 个词组、右 10 个中文（打乱）；先点左再点右，对绿错红、记错次（复用 `syn.js`） | 本地，成绩本地存 |
| ③ 选择题 | 10 题，每题挖空句 + **本组 10 个词组当选项**（中文 + 用法作线索）；**点一个立刻判分并自动进下一题**（可点「看解析」展开 why/trap）；顶部 10 格进度条 | 错题落库 |
| 批改总结 | 得分 X/10（连线错次、选择题错题清单）；「重做错题」「回看卡片」「下一组 →」；**错的题自动进词组错题本** | — |

复习闭环：
- 进组时若本机/后端有错题 → 顶部条「上次错了 3 题 · 去订正」（跳到那道题）；
- 错题本（`mistakes.html` 加「词组」一段）：题干 + 你选的 + 正确答案 + 解析 + 「去订正 →」；
- v2 再做间隔重复（SRS）。

### 2.4 页面地图与入口

| 页面 | 内容 |
|---|---|
| 首页 | 磁贴「PET 词组库」→ `phrases.html` |
| `phrases.html` | 分组视图（26 组卡片：几条 / 收藏几条 / 错题几道）→ 组页两个模式；URL 带 `?g=1`（错题本深链还带 `&mode=xbw&q=9`） |
| `collocations.html` | 「速查表」：老的 10 个一组清单 + 填空练习（从分组视图底部进） |
| `words.html` | 「我的词书」加了「词组」一段（释义 / 用法 / 例句 + 翻译 / 回词组库） |
| `mistakes.html` | 加了「词组（小霸王模式）」一段，错题「去订正」跳回那一组的那道题 |

## 3. 数据架构（技术架构师）

### 3.1 铁律：**内容**和**用户态**分开存

| | 存哪 | 为什么 |
|---|---|---|
| 词组 / 题目 / 选项 / 解析 | `data/phrases.json`（git 真源，构建期内联进页面） | 2 核 2G 静态站：内容不进请求链路；可离线、可导出、可 diff 审校 |
| 用户收藏 / 错题 / 进度 | MySQL | 要跨设备、要统计 |

`pet_phrase` 是**内容镜像表**（可选但推荐）：只为「用户词组表能 join 到标准内容」「谁被收藏/错得最多」这类查询。
它由 `tools/import-phrases.mjs` 从 `data/phrases.json` 幂等 UPSERT（不改内容，只同步）。

### 3.2 三张表（DDL 直接进 `server/migrate.mjs`，幂等）

**① `pet_phrase` 词组库（内容镜像）**

```sql
CREATE TABLE `pet_phrase` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `no`         SMALLINT UNSIGNED NOT NULL COMMENT '书上序号 1–254',
  `grp`        TINYINT  UNSIGNED NOT NULL COMMENT '组号（10 个一组）',
  `phrase`     VARCHAR(128) NOT NULL COMMENT '词组',                     -- ★
  `alt`        VARCHAR(128) NOT NULL DEFAULT '' COMMENT '等价说法（= groups of）',
  `meaning`    VARCHAR(255) NOT NULL DEFAULT '' COMMENT '中文意思',       -- ★
  `usage_note` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '用法（中文提示）',
  `example`    VARCHAR(512) NOT NULL DEFAULT '' COMMENT '例句',           -- ★
  `example_cn` VARCHAR(512) NOT NULL DEFAULT '' COMMENT '例句翻译',       -- ★
  `blank`      VARCHAR(128) NOT NULL DEFAULT '' COMMENT '题干里挖掉的那一块',
  `quest`      JSON NULL COMMENT '答案分析：{why, trap}',
  `audio`      VARCHAR(255) NOT NULL DEFAULT '' COMMENT '本组跟读音频（可选）',
  `status`     TINYINT NOT NULL DEFAULT 0 COMMENT '0 草稿 / 1 已审',
  `created_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_phrase_no` (`no`),
  UNIQUE KEY `uk_phrase_text` (`phrase`),
  KEY `idx_phrase_grp` (`grp`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='PET 词组库（内容镜像，真源 data/phrases.json）';
```

**② `user_phrase` 用户词组表（你要的那 5 个字段：用户id / 词组 / 中文意思 / 例句 / 例句翻译）**

```sql
CREATE TABLE `user_phrase` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT UNSIGNED NOT NULL COMMENT 'user.id',              -- ★用户id
  `phrase_id`   BIGINT UNSIGNED NOT NULL COMMENT 'pet_phrase.id',
  `level`       VARCHAR(16) NOT NULL DEFAULT 'PET',
  `phrase`      VARCHAR(128) NOT NULL COMMENT '词组（快照）',             -- ★词组
  `meaning`     VARCHAR(255) NOT NULL DEFAULT '' COMMENT '中文意思（快照）',  -- ★中文意思
  `example`     VARCHAR(512) NOT NULL DEFAULT '' COMMENT '例句（快照）',      -- ★例句
  `example_cn`  VARCHAR(512) NOT NULL DEFAULT '' COMMENT '例句翻译（快照）',  -- ★例句翻译
  `source_type` TINYINT NOT NULL DEFAULT 3 COMMENT '3=词组',
  `source_title` VARCHAR(255) NULL,
  `created_at`  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_phrase` (`user_id`, `level`, `phrase_id`),
  KEY `idx_user_phrase_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户收藏的词组（带内容快照）';
```

> 为什么带「快照」列：词书/复习页读的时候不必 join，内容改了老收藏也不烂；
> 和现有 `pet_word` + `user_word` 是同一套路（内容表 + 关联表），只是把常用字段冗余了一份。

**③ `pet_phrase_mistake` 词组错题表（用户id / 原题 / 选择项）**

```sql
CREATE TABLE `pet_phrase_mistake` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT UNSIGNED NOT NULL COMMENT 'user.id',              -- ★用户id
  `phrase_id`   BIGINT UNSIGNED NOT NULL,
  `phrase_no`   SMALLINT UNSIGNED NOT NULL COMMENT '书上序号',
  `phrase`      VARCHAR(128) NOT NULL COMMENT '词组（快照）',
  `stem`        VARCHAR(512) NOT NULL COMMENT '原题（挖空后的句子）',      -- ★原题
  `chosen`      VARCHAR(128) NOT NULL COMMENT '你选的那个（选项文本）',    -- ★选择项
  `chosen_k`    CHAR(1) NOT NULL DEFAULT '' COMMENT '选项字母',
  `correct`     VARCHAR(128) NOT NULL COMMENT '正确选项文本',
  `correct_k`   CHAR(1) NOT NULL DEFAULT '' COMMENT '正确选项字母',
  `wrong_count` INT UNSIGNED NOT NULL DEFAULT 1 COMMENT '同题错了几次',
  `created_at`  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ph_mistake` (`user_id`, `phrase_id`),
  KEY `idx_ph_mistake_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='词组选择题错题记录';
```

> **为什么另开一张，不塞进 `pet_mistake`**：现有表是给阅读题用的 —— 题号限 `1–99`、
> `chosen/correct` 限 `A–Z` 单字母、唯一键是 `(user_id, slug, q_n)`。词组错题要存**原题文本 +
> 选项文本**（换选项/改标题后错题本还能看懂），语义不同，硬塞会把两边都拧巴。
> `pet_mistake` 一个字节都不动，阅读错题本零回归。

### 3.3 容量与性能（2 核 2G 的现实）

- 内容：254 条 × ~1KB ≈ 260KB（gzip 后 ~60KB）；`pet_phrase` 才 254 行，随便查。
- 用户态：一个学生 254 × 2 行量级；索引都命中 `user_id` 前缀，单表 < 10 万行无压力。
- 页面：`phrases.html` 全量内联 ≈ gzip 40–60KB，比一篇文章还小；不新增请求链路。

### 3.4 迁移与回滚

- 全部进 `server/migrate.mjs`（现有风格：`information_schema` 查存在性 + `--dry`）；
  三张表都是**新增**，不动老表 → 回滚 = `DROP TABLE` 三张 + 删接口分支。
- `tools/import-phrases.mjs`：`data/phrases.json` → `pet_phrase` 幂等 UPSERT（`--dry` 打印差异）。

## 4. 接口契约（技术架构师 ↔ 前端架构师）

| 方法 | 路径 | 入参 | 返回 | 说明 |
|---|---|---|---|---|
| POST | `/api/favs/add` | `{phone, kind:"phrase", phrase, meaning, usageNote?, example, exampleCn, no?, sourceTitle?}` | `{ok, phraseId}` | **扩展现有接口**（加一个 kind 分支），前端 `pushOp` 加 `type:"p"` |
| POST | `/api/favs/remove` | `{phone, kind:"phrase", phrase}` | `{ok, removed}` | 同上 |
| GET | `/api/favs` | `?phone=` | `{ok, items:[…, {type:"p", key:"a couple of", cn, ex, exTr, no, ts}]}` | 词书页一并显示 |
| POST | `/api/phrase-mistakes` | `{phone, no, phrase, stem, chosen, chosenK, correct, correctK}` | `{ok}` | 同题重复错 → `wrong_count + 1` |
| GET | `/api/phrase-mistakes` | `?phone=` | `{ok, items:[{no, phrase, stem, chosen, correct, count, ts}]}` | 错题页现拉 |
| （可选） | `GET /api/phrases?g=1` | | `{ok, items:[…]}` | 只有将来要「服务端出题」时才需要；v1 内容内联，不用它 |

离线与降级（沿用现有约定，不发明第二套）：

- **收藏**：本地先写（界面只认本地）→ 队列 → 联网补写；失败永久 400 的条目丢弃并 `console.warn`；
  拉取时 `reconcile` 对账（换设备恢复）。
- **错题**：直连、不排队（错一次报一次；报不上就算，别拦着学生做题）。
- 没登录 / 没网络 / `file://`：门禁放行，功能退化成「纯本地」—— 学习不被打断。

服务端测试：`server/test.mjs` 按现有风格加 8–10 条（phrase add/remove、错题计数、字段超长 400、bad kind 400）。

| `phrases.html` | 词组库（单页，`?g=1` 切组）：顶栏两个 tab = 经典模式 / 小霸王模式；底部「速查表」 |
| `engine/phrase.js` | 经典模式：单卡翻阅 + 小黑板 + 历史 + 收藏 + TTS |
| `engine/xbw.js` | 小霸王：三关状态机 + 批改（连线部分照搬 `syn.js`，选择题照搬 `col.js` 的点选） |
| `build.mjs` | 新增 `renderPhrases()` + PAGES 注册 + 首页磁贴改名 |

### 5.2 复用清单（具体到「哪一块代码怎么用」）

| 能力 | 现在在哪 | 怎么用 |
|---|---|---|
| 门禁 / 登录态 / 主题 / 昵称角标 | `store.js` 的 `guard / mountWho / mountTheme` | **原样调用**，一行不改 |
| 收藏（本地即生效 + 队列 + 对账） | `store.js` `addFav/listFav` + `pushOp` | 加 `type:"p"` 分支（3 行） |
| 错题 | `store.js` `addMistake/listMistakes` | 新增 `addPhraseMistake/listPhraseMistakes`（同形状，换路径） |
| 分词 / 词条查找 / 词组高亮 | `app.js` `tokenize/lookup/renderTokens` | **照抄形状**进 `phrase.js`（不动 app.js：那是被 smoke 罩得最密的文件） |
| 小黑板 | `app.js` `showAnalysis` | 精简三态：词组条 / 单词条 / 题目解析 |
| 历史浮层 | `app.js` `renderHistory` + `pet:hist:v1:<slug>` | 按组隔离：`pet:hist:v1:phrases-1` |
| 连线题 | `syn.js` 配对与计分 | 第二关逻辑直接搬 |
| 挖空 / 点选填充 | `col.js` | 第三关改成 4 选 1 + 自动跳题 |
| TTS（英音 0.75x） | `app.js` TTS / `col.js` `speak()` | 原样口径 |
| 错题列表页 | `mlist.js` + `mistakes.html` | 加「词组」一段（同一页，两块） |

设计约定（照现有工程规矩）：颜色只走令牌（暗色零成本）、不新增 `@media` 断点（只认 1099）、
每个新页面在 smoke 里成套断言（`expectScripts`、门禁、交互）。

### 5.3 状态与交互

```
state = {
  g: 1,            // 当前组
  mode: "classic", // classic | xbw
  card: 0,         // 经典模式：第几张（0-9）
  hist: [],        // 历史（本地，按组隔离）
  favs: {},        // 已收藏词组（小写 key）
  xbw: null        // 小霸王一轮的状态：{stage, play:{i,timer}, link:{…}, quiz:{i,ans,wrong}}
}
```

- 键盘：`←/→` 翻卡；`空格` 播放/暂停；选择题 `1–4` / `A–D` 作答；`Esc` 关浮层。
- 窄屏（<1100）：小黑板走底部抽屉（与文章页同一套 CSS 思路）；小霸王三关全屏化（一次只出现一道题）。
- 无障碍：所有可点元素是 `<button>`；进度条带 `aria-live`；动效尊重 `prefers-reduced-motion`（自动播放默认不静音？见问题 5）。

### 5.4 性能

- 单页内联全量词组（254 条）→ gzip ~40–60KB；构建期预压缩（现有 `.gz` 流程）直接受益。
- 自动播放用一次 `speechSynthesis` + `setTimeout` 链，切页/离开时 `cancel`（现有 TTS 已这么做）。
- 图片/音频：音频 26 个 mp3 ≈ 14MB，**默认不进 git**（放 `assets/audio/` 由 `.gitignore` 决定，见问题 5）。

## 6. 内容生产流水线（254 条 → 题库）

| 步 | 做什么 | 谁 |
|---|---|---|
| 1 | 抽 + 洗（标点、拆词、范围号；列位漂移） | 脚本（规则），我复查 |
| 2 | 分组：10 个一组，补 `grp` / `blank` | 脚本 |
| 3 | 出题：题干挖空 + 3 个干扰项（同组优先、结构相近）+ `why` / `others` | 我生成草稿 |
| 4 | **审**：一题多解、干扰项也成立、解析与句意不符 → 出「疑点清单」 | 你抽查（每组 10 条，建议抽 3 条） |
| 5 | 入库 + 校验：`verify`/smoke 加数据契约（4 选项、答案唯一存在、干扰项 ≠ 答案、`blank` 是 `ex` 子串） | 脚本 |
| 6 | 上线：先第 1 组，验证完再每组 10 条往前推 | 我 |

每批的验收标准（写进 CLAUDE.md）：

- 254/254 条字段齐全，`quest.opts` 恰好 4 个、`ans` 命中其一、3 个干扰项互不相同且 ≠ 答案；
- `blank` 必须是 `ex` 的子串（题干由它生成，数据不许漂）；
- 每组跑一次 smoke：卡片数、选项数、判分、错题落库、门禁全绿。
